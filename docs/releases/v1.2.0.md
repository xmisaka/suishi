## 这个应用是什么

四屏主标签，一件核心的事：**把日子记下来，然后看得见它还有多远。**

- **天象盘（首页）** —— 一屏只做一件事：把一年摊成一张圆盘。环本身就是时间光带，
  十二段对应十二个月；光点就是你的日子，落点由真实历法算出来。
  圆盘可以拖着转，松手时焦点会落到附近的日子上。
- **全部** —— 不按创建时间排，按**时间距离**分段（今天 / 一周之内 / 一个月内 / 三个月内 /
  一年之内 / 一年之后 / 已经过去）。一年几十个日子平铺下来看不出哪些该现在准备；
  分段把时间距离变成视觉距离。已过去的另起一段压到最后 —— 它们不再是提醒，而是存档。
- **记一笔** —— 只问三件事：叫什么、哪天、怎么重复。其余（标记色、置顶、备注）都放在下面，不抢视线。
- **详情** —— 大号倒计时占住上半屏，下面才是事实。公历与农历**两个都列出来**，
  不管当初是用哪个历法建的。
- **四套主题** —— 玄夜（墨底暖金，默认）/ 苍青（墨蓝月白）/ 墨玉（墨绿玉色）/
  素笺（暖米白配赭石棕）。**不跟随系统深色**：主界面是一枚星盘，浅色档下它只是张统计图，
  跟随系统会让同一个应用在白天和夜里变成两个东西。选择权交给用户。

**农历是认真的那部分。** 农历条目**只存原始农历值**（年 / 月 / 日 / 是否闰月），
换算出的公历日期只在运行时算、不落库 —— 农历一旦公历化就会逐年失真：
今年八月十五是 9 月 25 日，明年不是。周期规则四档（`once` / `yearly` / `monthly` / `weekly`），
边界在解析层钳住：公历 2 月 29 日在非闰年钳到 28，31 号在小月钳到月末。

**数据出口是文件，不是账户。** 导出写一个 JSON 到缓存目录再交给系统分享面板，
想放哪就放哪（文件管理器、网盘、发微信给自己）。导入**先看再动** —— 先弹预览摊开导出时间、
条数、文件名，再选「合并」还是「替换」；「替换」还要再过一道红色确认。
备份含回收站条目、不含界面偏好。

> **无本地通知。** 这一项是刻意不做的（已定案），所以不会有到日提醒 —— 打开应用才看得到。

## 本版更新（相对 v1.1.0）

这一版只动了一样东西：**图标**。功能与数据层未变，界面骨架未变。

- **App 图标去掉那圈细环** —— 它不是刻度也不是边界，只是一道装饰；可它偏偏是整个标记的
  最外沿，比字本身还大一圈，等于把标记的体量让给了一根发丝线。去掉之后，最外沿改由
  「夕」的长撇尖构成，**框让位给字**。
- **字同时收小一档** —— 字高从占可见圆 **66.5% 收到 48.8%**。参照系是姊妹项目格物那枚图标
  （它的字高只占可见圆 39.8%），但金色细笔画压在墨底上比棕字压在浅底上更吃尺寸，
  照搬 40% 会显得单薄，所以取了这一档。
- **顺带修掉一处不一致** —— 主题图标（单色版）原先单独把字放大到 `cap 0.328`，
  而彩色版停在 `0.300`，导致**主题图标里的字比普通图标大 9%**。现在两版共用一个字号，
  逐像素同形（alpha 最大差 **0**）。
- **启动图跟着补回体量** —— 标记变小后如果不动 `imageWidth`，启动画面上的标记会从
  84.9 dp 缩到 58 dp。已把 `imageWidth` 从 132 提到 **194**，标记外径回到 **84.9 dp**，
  与 v1.1.0 的观感一致。

<details>
<summary><b>展开：为什么「去掉一道环」值得单独发一版</b></summary>

原先那圈金线的外接半径是**画布 × 0.3233**，在自适应图标的安全区里已经贴到边
（上限 0.3333）。也就是说：整个标记的**视觉体量**由一根 1~2 px 宽的线决定，
而线本身不承载任何信息 —— 不表示进度、不表示刻度、不圈定范围。

去掉之后：

| | 改版前（带环） | 改版后（无环） |
|---|---|---|
| 最外沿由谁构成 | 那圈细金线 | 「夕」的长撇尖（最远点在 131°） |
| 墨迹外接半径 ÷ 画布 | 0.3233 | **0.216 ~ 0.220** |
| 字高 ÷ 可见圆直径 | 66.5% | **48.8%** |
| 主题图标里的字 | 比普通图标大 9% | 与普通图标**逐像素同形** |

外接半径降到 0.22 之后，标记在自适应图标的遮罩里留出了真正的余量 ——
圆形、方圆形、圆角方形三种启动器遮罩下都不会被切到（验收实测：**可见圆外 0 px**）。

</details>

<details>
<summary><b>展开：图标验收（47 项全通过）</b></summary>

图标这类东西的麻烦在于**改了不报错，只画错**。所以有一套按像素读数的验收脚本
（`expo-android-icons` 技能自带，`verify_android_icons.py`），本次结果：

**时间戳** —— 4 个原生资源都晚于素材（+1261 ~ +1262 s），确认是新生成的，不是残留

**legacy 图标（5 个密度档）** —— `ic_launcher` 与 `ic_launcher_round` 四角 alpha 全为 0、
边中点为底色（读数 `(21,20,16)`，期望 `(22,20,15)`）

**48px 档可辨性** —— 字形像素高度 **16 px**（阈值 ≥ 10）

**自适应层安全区（5 个密度档 × 2 图层）** —— 外接半径 ÷ 画布 = **0.2162 ~ 0.2196**，
上限 0.3333；**可见圆外 0 px**

**色版与单色版同形** —— **alpha 最大差 0**

**legacy 圆角不切字形（5 个密度档）** —— 圆角外 0 px

**启动图前景占比（5 个密度档）** —— 量得 0.1474 ~ 0.1475，期望 0.1476；
标记外径 **84.9 ~ 85.0 dp**

</details>

## 安装

**方式一 · 手机上直接安装（推荐）**

1. 把 APK 传到手机（微信 / QQ 文件传输、数据线、网盘均可）
2. 在手机上点开这个文件
3. 系统提示「未知来源」时允许安装：
   设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选中你用来打开该文件的 App → 允许
4. 安装完成后桌面出现「岁时」图标

**方式二 · 数据线 + adb**

```bash
adb install -r suishi-v1.2.0-arm64.apk
```

若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（之前用 Expo Go 装过，或用了另一套签名），
先 `adb uninstall com.suishi.app` 再装 —— **卸载会一并清掉应用内全部数据**。
需要保留的话先在「我的 → 数据」里导出备份，装完再导入。**覆盖安装（不加 uninstall）不受影响。**

<details>
<summary><b>图标换了但桌面没变？</b>（启动器缓存，属正常）</summary>

桌面上的图标是启动器**缓存**过的。装完新包后如果看着还是旧样子：

- 多数手机的启动器会在几秒到几十秒内自己刷新；
- 不刷新的话，把「岁时」从桌面拖掉再重新从应用列表拖回来；
- 再不行就重启一次手机 —— 启动器只在开机时重读一遍图标资源。

（图标资源本身已从包内反查核对：彩色层 / 单色层 / 圆角层三套都换成了新版。）

</details>

<details>
<summary><b>权限清单</b>（实际申请 4 项）</summary>

| 权限 | 用途 |
|---|---|
| `INTERNET` | 由 Expo 运行时带入，**应用自身不发起任何网络请求** |

| `READ/WRITE_EXTERNAL_STORAGE` | 由 `expo-file-system` 带入，且都带 `maxSdkVersion="32"` —— 只在 Android 12L 及以下才会申请，Android 13 以上根本不请求 |

**备份导出不需要任何存储权限** —— 走的是应用自己的缓存目录 + 系统分享面板。

已从模板默认清单中**移除**：`RECORD_AUDIO`、`SYSTEM_ALERT_WINDOW`。没有录音、没有悬浮窗。
